1729, and the shape of attention.

A thousand seven hundred twenty-nine tokens. Thirty-two heads. One beautiful chain of matrix shapes. No tiny toy dimensions, no thousand-row drawings, and no need to memorize a diagram that makes no sense.

Our chosen number

Why 1729?

Because it is memorable for a reason. The Hardy–Ramanujan number is the smallest positive integer expressible as the sum of two positive cubes in two different ways. And a token count, unlike head dimensions, has no obligation to divide neatly by 32.

1729 = 1³ + 12³
1729 = 9³ + 10³

Our one useful division: 4,096 ÷ 32 = 128. That's the ordinary multi-head setup we'll use throughout. There is no similar requirement for 1,729 or 50,000.

Dots stand in for all the rows and columns we sensibly refuse to draw.

?
“But the model knows 50,000 vocabulary tokens. Why aren't there 50,000 rows?”
✓
Because we look up embeddings only for the 1,729 positions actually present. The full 50,000-entry embedding table is a learned lookup book, not our input sequence.

Position information is also incorporated (the exact method depends on the architecture). It doesn't change our basic input shape: 1,729 × 4,096.

02 / THE HEADS

Each head sees all 4,096 features.

Not a chopped-off slice. Each head applies its own learned projections to the full input. And each head has three: one for queries, one for keys, one for values.

?
“So head one gets the first 128 input features, head two gets the next 128...?”
✓
Almost, but here's the crucial correction: every head can mix information from all 4,096 input features. Its learned 4,096-by-128 matrices decide how.

128 is the inner dimension, so it disappears. The two 1,729 dimensions remain.

Read across a row

Row 100 contains how token position 100, acting as a query, scores every candidate key position. Position 25 is the entry in column 25.

Read down a column

Column 25 tells us how all the query positions score the key at position 25. This is why swapping Q and K changes the meaning.

Yes, it's square: 1,729 × 1,729 = 2,989,441 raw scores per head. A big input gives you a big attention matrix even though each head's feature width is just 128.

Row 1: one place to look.

Only column 1 survives. The other five entries are −∞, so after row-wise softmax, the first attention weight is 1 and the rest are 0.

Scale this up: row 1 of our real matrix has one allowed entry. Row 1,729 has all 1,729 allowed entries.

A = softmaxacross each row ( S + causal mask )

The result A is our attention weight matrix, still 1,729 × 1,729. Every row sums to 1, and every masked position receives probability 0. This is the first of two different softmax operations in our story.

05 / VALUES

Q and K choose where. V supplies what.

We've got attention weights. Now we use them to blend the value vectors. Every output row becomes a weighted sum of information retrieved from allowed token positions.

The shared inner 1,729 vanishes in matrix multiplication. What remains is one 128-dimensional output vector per position.

A concrete mental picture

Suppose query position 100 places 70% of its attention on position 25 and 30% on position 80, with negligible weight elsewhere. Its output vector is roughly 0.7 × V25 + 0.3 × V80.

The subtle point

It's the same set of attention weights used to combine all 128 value features. Each feature gets its own weighted sum; the weights don't change from feature to feature within that output row.

128 feature sums, represented by just a few bars.
Names worth keeping straight: A is the attention weight matrix (1,729 × 1,729). AV is the attention output (1,729 × 128, for one head).

In our setup, the learned output projection WO is 4,096 × 4,096. It mixes the concatenated head features without changing the final width.

This is one multi-head attention sublayer, not the entire transformer. Other operations—including feed-forward networks, residual connections, and normalization—and more transformer layers build the final contextual representations. The model's width typically stays 4,096.

?
“Wait. Does the last row bear all the responsibility for predicting the next token?”
✓
Yes—for the next-token prediction at inference time. Its representation already incorporates relevant information from earlier positions through causal attention across the transformer layers. The other rows helped build that context.

The embedding book at the entrance

There are 50,000 learned vocabulary entries, each containing a 4,096-feature vector. Our 1,729 input positions look up only the entries they need; repeats are perfectly possible.

The scoring book at the exit

The output projection has one column per vocabulary item: 4,096 × 50,000. It produces a logit for every possible next token. Some models reuse the embedding table transposed, called weight tying.

For next-token generation, compare possible vocabulary tokens. Those 50,000 probabilities sum to one.

Small but important nuance: During training, a causal language model commonly predicts a next-token target at every position, so it can project all 1,729 hidden rows into vocabulary logits. During generation, only the last row is needed to choose the next token.
